Arrays vs Lists

Both are ways of storing an ordered collection of values. The difference is how they're stored in memory, and that difference drives every other trade-off below.

What each one is

Array

A block of memory of fixed size, allocated all at once, holding elements of the same type in contiguous memory locations. Each element is found using its index, which the computer converts directly into a memory address — that's why array access is instant no matter how big the array is.

List

A collection that can grow or shrink at run time. In many languages (Python's list, Java's ArrayList) this is implemented as a dynamic array behind the scenes — a block of memory that gets reallocated and copied when it runs out of room. A linked list is a stricter version: separate nodes scattered in memory, each one storing a value and a reference (pointer) to the next node.

Why this matters for sorting

All four sorting algorithms on this site — Bubble, Selection, Insertion and Merge Sort — are written against arrays (Python lists used as fixed-size arrays). They rely on O(1) index access: comparing arr[j] and arr[j+1], or writing directly to arr[k], has to be instant for these algorithms' time complexity (e.g. O(n²) or O(n log n)) to hold. If you implemented the same algorithms over a true linked list, every indexed access would cost O(n), and the overall running time would blow out — which is one reason array-style storage is the standard structure for teaching and implementing sorting algorithms, even though the syllabus also asks you to know about files and linked lists as alternative data structures.

Quick self-check

  • Why is arr[500] just as fast as arr[0] in an array, but not in a linked list?
  • Why does inserting into the middle of an array-based list require shifting elements, while a linked list doesn't?
  • What has to happen when a dynamic array (like a Python list) runs out of spare capacity and you append one more item?
